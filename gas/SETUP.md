# 報告フォームの受付側（Google Apps Script）の設置手順

ゲーム内の「不具合・ご意見を報告する」から送られた報告を、あなたの Google スプレッドシートに保存するための設定です。
**Google アカウントでの操作はすべてご自身で行ってください**（Claude は代行しません）。このフォルダ（`gas/`）は GitHub Pages では公開されません。

- ソースコード：`gas/Code.gs`（そのまま貼り付けます。中に秘密の値は入っていません）
- 送信先 URL をゲームに設定するまでは、ゲームの報告フォームは「送信先が未設定」と表示して送信できません（仮の URL は入れていません）

## 1. スプレッドシートを作る

1. Google ドライブで新しいスプレッドシートを作ります（名前は自由。例：`ABYSSAL LEGENDS 報告`）。
2. **共有設定は「自分だけ」のままにしてください。** 他の人に編集権限を渡す必要はありません。

## 2. スクリプトを貼り付ける

1. スプレッドシートのメニュー「拡張機能」→「Apps Script」を開きます（このスプレッドシートに紐づいたスクリプトになります）。
2. 最初からある `コード.gs` の中身をすべて消し、`gas/Code.gs` の内容を貼り付けて保存（Ctrl/⌘+S）します。
3. 上部の関数選択で **`setup`** を選び「実行」を押します。初回は権限の確認が出ます（自分のアカウントでの承認です）。
   - 成功すると、シート「報告」が作られ、1 行目に見出し（A〜M 列）、L 列「対応状況」に選択肢（未対応・対応中・対応済み・保留・対応不要）が設定されます。
   - 既に「報告」シートがある場合は、既存のデータを消さずに選択肢だけ設定します。
   - `setup` は何度実行しても安全です（見出しは空のときだけ書き、既存の報告は消しません）。新しいシートの行数・列数が足りない場合は、先に増やしてから設定します。報告が増えてシートの行数を超えたときも、保存のたびに自動で行を増やします。

| 列 | 内容 | 列 | 内容 |
|---|---|---|---|
| A | 受付日時（日本時間） | H | ゲームバージョン |
| B | 報告ID（`BR-日付-連番`） | I | OS情報 |
| C | 報告種類 | J | ブラウザ情報 |
| D | タイトル | K | 返信先（入力があった場合のみ） |
| E | 詳細 | L | 対応状況（初期値「未対応」） |
| F | 発生頻度 | M | 管理メモ（自由記入） |
| G | 再現手順 | | |

## 3. ウェブアプリとして公開する

1. Apps Script 画面の右上「デプロイ」→「新しいデプロイ」。
2. 種類の歯車から「ウェブアプリ」を選びます。
3. 設定は次のとおりにします。
   - **次のユーザーとして実行：自分**（スプレッドシートの編集はこの権限で行われます。権限そのものは外に出ません）
   - **アクセスできるユーザー：全員**（「Google アカウントを持つ全員」ではなく「全員」。ログイン不要でゲームから送れるようにするため）
4. 「デプロイ」を押し、表示される **ウェブアプリの URL**（`https://script.google.com/macros/s/…/exec`）をコピーします。
   - この URL は公開されます（ゲームの `index.html` に書くため）。**URL を知っている人は誰でも報告を送れます。** スプレッドシートの編集権限が渡るわけではありません。
5. コードを変更したときは「デプロイを管理」→ 鉛筆アイコン →「バージョン：新バージョン」にして更新してください（保存しただけでは公開中のコードは変わりません）。

## 4. ゲームに送信先を設定する

`index.html` の `AL.CONFIG.REPORT.ENDPOINT`（`js/core/config.js` 区画の中）に、コピーした URL を貼ります。**設定する場所はここだけです。**

```js
REPORT: {
  ENDPOINT: 'https://script.google.com/macros/s/（あなたのID）/exec',
  ...
}
```

- `https://script.google.com/macros/s/…/exec` の形以外は、ゲーム側が送信を拒否します（設定ミスで別のサイトへ送らないため）。
- 設定した変更はテストして PR を作り、公開の手順（通常のマージ・公開）に従ってください。

## 5. 動作確認

1. ブラウザで URL を開く → `{"ok":true,"service":"abyssal-legends-report"}` と表示されれば、公開できています。
2. ゲームの「その他」画面 →「サポート」（PC では上部メニューの「サポート」）で、種類・タイトル・詳細を入れて送信し、「報告を受け付けました」と報告ID が出ることを確認します。
3. スプレッドシートの「報告」シートに 1 行増え、A〜M 列が入っていること（対応状況が「未対応」）を確認します。
4. 次も確認してください：
   - メールアドレスを空欄にして送れる／不正な形式だと送れない
   - 同じ内容を続けて送ると、ゲーム側で一定時間（60 秒）止まる
   - `=1+1` や `+SUM(1)` で始まるタイトルが、数式として計算されず文字のまま保存される
   - 機内モードで送信すると「通信エラー」が表示され、入力内容が残っている
   - スマートフォンの実機（iPhone Safari など）で送れる

> **未検証：** 実際の Google Apps Script・スプレッドシート・ブラウザからの送信（CORS を含む）は、Claude の環境では確認できていません。上の確認で動作を確かめてください。

## 6. 公開中のコードがやっている制限

- **サーバー側の検証：** 種類・発生頻度は選択肢のみ、タイトル 100・詳細 3000・再現手順 2000 文字まで、メールは形式チェック、文字以外の型や制御文字は拒否または除去。リクエスト本文は 20000 文字まで。
- **排他制御：** 保存は `LockService`（スクリプトロック）の中で、採番と書き込みを行います。取得できなければ「受付が混み合っています」と返します。
- **重複防止：** 再送された同じ送信（requestId）は、6 時間以内なら二重に保存せず、同じ報告IDを返します。
- **送信頻度の制限：** ウェブアプリ全体で 1 分 10 件・1 時間 60 件・1 日 200 件まで。シートが 20000 行に達したら受け付けません。
- **数式の無害化：** `= + - @` で始まる文字は先頭に `'` を付け、列は文字列として保存します（スプレッドシートの数式インジェクション対策）。
- **応答：** エラーには内部情報を含めず、`code` だけを返します。詳細はスクリプトの「実行数」のログにだけ残ります。
- **受け取らない情報：** セーブデータ・所持品・ゲームの進行状況は、ゲーム側が送らず、サーバー側も受け付けません。メールアドレスは入力があった場合だけ保存します。

### 限界（重要）

公開された URL へのリクエストは、ゲームを経由せずに誰でも送れます。クライアント側（ゲーム）の入力チェックや 60 秒の間隔は、悪意のある送信を防げません。サーバー側の上限で被害を抑えますが、次の限界があります。

- 送信者を区別できない（Apps Script では接続元の IP を取得できない）ため、頻度の制限は**全体の合計**です。大量に送られると、本物のプレイヤーの報告も一時的に受け付けられなくなる可能性があります。
- その場合は、デプロイを無効化する／新しい URL に作り直して `index.html` を更新する、で止められます。
- 蜜壺の欄（`website`）は、単純な自動送信を弾く程度の効果です。
- 報告の内容（URL・スパム文面など）はそのまま保存されます。スプレッドシートの内容は信用せず、リンクを不用意に開かないでください。

## 7. トラブルシューティング

| 症状 | 確認すること |
|---|---|
| ゲームが「送信先が未設定」と出る | `AL.CONFIG.REPORT.ENDPOINT` が空、または `…/macros/s/…/exec` の形ではない |
| 「通信エラー」になる | 公開の「アクセスできるユーザー」が「全員」か。URL の末尾が `/exec` か（`/dev` はだめ）。ブラウザで URL を開いて `ok:true` が出るか |
| 「受付エラー」（受け付けられませんでした） | 文字数・形式を確認。コード変更後に「新バージョン」でデプロイし直したか |
| 「受付が混み合っています」 | 同時に多数の送信があった。少し待って再送（同じ内容は重複しません） |
| 「送信が集中している」（rate_limited） | 頻度の制限（1 分 10 件など）に達した。時間をおく。上限は `Code.gs` の `RATE_LIMITS` |
| シートに行が増えない | `setup()` を実行したか。シート名が「報告」か。デプロイを更新したか。Apps Script の「実行数」でエラーを確認 |
| 権限の承認画面が出る・「このアプリは確認されていません」 | 自分で作ったスクリプトなので、詳細 →「（安全ではないページ）に移動」で承認する（自分のアカウント上だけの設定） |
| 数式の警告・文字化け | `setup()` 後に列の書式を変えていないか |
